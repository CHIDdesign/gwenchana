# 괜차나 (Gwenchana) — 최종 아이디어 정리

Oct 29, 2026

## 한 줄 정의

**사고 직후, 차가 "제3의 조수석 탑승자"가 되어 안전 행동을 안내하고, 사고 순간의 블랙박스 영상과 조작 기록을 묶어 경위를 설명하고, 참고할 기준을 알려주는 Pleos Connect 앱.**

- 판사가 아니라 **증인**이다. 누가 잘못했는지 판정하지 않는다.
- 운전자마다 상황이 다르므로, 같은 사고라도 **누가 운전 중이었고 어떤 차를 타고 어디서 났는지**에 따라 안내가 달라진다.
- 이름 그대로, 기억이 엇갈릴 때 사람 대신 **차에게 물어본다**.

## 문제 정의

사고 직후 운전자는 당황해서 **안전 행동 순서를 놓치고, 기억이 엇갈리고, 무엇을 기준으로 다퉈야 할지 모른다.**

| 문제 | 근거 |
| --- | --- |
| 분쟁이 계속 늘어난다 | 과실비율 분쟁 심의 청구 2013년 26,093건 → 2024년 156,812건 ([보험연구원](https://www.kiri.or.kr/pdf/연구자료/연구보고서/nre2026-06_2.pdf)) |
| 서로 자기가 피해자라고 기억한다 | 분심위 심의 청구 운전자의 82.8%가 본인이 피해자라고 인식, 인식 차이가 분쟁의 주요 원인 ([파이낸셜뉴스](https://www.fnnews.com/news/202204201139201325)) |
| 사실 확인 주체가 약하다 | 일본은 경찰이 사실 확인에 개입, 한국은 보험사 직원과 블랙박스에 의존. 대물 수리 대비 분쟁 비율 한국 5.4%(2024), 일본 0.03%(2023) ([보험연구원](https://www.kiri.or.kr/pdf/연구자료/연구보고서/nre2026-06_2.pdf)) |
| 판단 기준은 이미 일관적이다 | 분심위 결정 수용 90%, 소송 시 법원 인용 89% (2023) — 병목은 판단이 아니라 **사실 합의** ([보험연구원](https://www.kiri.or.kr/pdf/연구자료/연구보고서/nre2026-06_2.pdf)) |
| 현장 대처를 잘못하면 더 위험하다 | 고속도로 2차사고 치사율 54.3%, 일반사고의 6.5배, 고속도로 사망자 5명 중 1명 ([한국도로공사 2024-03-19](https://www.ex.co.kr/portal/biz/bbs/layout1/selectBoardArticle.do?bbsId=BBSMSTR_000000000183&nttId=26696)) |

한·일 차이의 원인을 경찰 개입 하나로 단정할 수는 없다. 기획서에는 "중립적 사실 확인이 분쟁을 줄일 수 있다"는 해석으로 쓴다.

## 사용자 유형과 맞춤화

**사고는 누구에게나 나지만, 필요한 도움은 사람마다 다르다.** 사회초년생만 노리면 시장이 작다. 면허 1년 미만 운전자는 전체 사고의 2.5%이고, 15년 이상 운전자가 60.6%를 차지한다(2019\~2023년 연평균, 사고 비중 기준이며 1인당 사고율은 아님, [이투데이](https://www.etoday.co.kr/news/view/2377484)). 그래서 **같은 3단계 기능을 유형별로 다르게 보여주는 구조**로 간다.

| 사용자 유형 | 근거 | 사고 직후 가장 필요한 것 | 앱의 맞춤 방식 |
| --- | --- | --- | --- |
| 첫 차 오너·사회초년생 | Pleos 기본 탑재 신형 아반떼가 '국민 첫차'로 불림 | 무엇부터 해야 하는지 | 단계별 상세 안내, 용어 풀이, 체크리스트 |
| 숙련 운전자·직장인 | 면허 15년 이상이 사고의 60.6% ([이투데이](https://www.etoday.co.kr/news/view/2377484)) | 빨리 끝내고 본업으로 복귀 | 간결 모드: 안전 안내 후 바로 기록서 생성·공유 |
| 고령 운전자 | 2023년 사고의 20.0%, 사망 사고의 29.2% ([서울신문](https://m.seoul.co.kr/news/2025/01/24/20250124500236)) | 작은 글씨 없이 이해하기, 가족 연락 | 음성 중심 안내(TTS), 큰 버튼, 보호자 연락 버튼 |
| 렌터카·카셰어 이용자 | 렌터카 사고의 26.3%, 사망의 44.0%가 20대(2020\~2024년 8월, [위키트리](https://www.wikitree.co.kr/articles/1071797)) | 낯선 차·낯선 지역에서 위치 설명, 대여사 연락 | 주소 자동 표기, 대여사 연락처, 계약 보험 확인 안내 |
| 아이·가족 동승 운전자 | 근거 수치 미확보 (인터뷰로 보완) | 동승자 안전과 대피 | 동승자 먼저 대피 안내, 아이 동승 시 문구 전환 |

**맞춤화는 두 축으로 한다.**

1. **사람 축 (내 정보)**: 안내 방식(상세·간결·음성), 내 차·렌터카, 보험사·렌터카 회사·보호자 번호를 운전자가 앱 설정 "내 정보"에서 직접 고른다. **향후 계획:** Pleos 차량 프로필과 계정에 연동해 프로필마다 설정이 저절로 따라오게 한다(프로필 서비스는 signature·privileged 권한이라 일반 앱은 쓸 수 없음, 운영국 안내 2026-11-05).
2. **상황 축 (차 데이터)**: 고속도로인지 시내인지(위치), 정차했는지(기어 P), 야간인지(시각)를 차가 판단해 안내 순서를 바꾼다.

같은 사고라도 "고속도로 + 고령 운전자"는 음성으로 대피부터, "시내 이면도로 + 숙련 운전자"는 촬영 체크리스트와 기록서부터 보여준다.

## 핵심 기능 3단계

**안전 → 기록 → 참고, 세 단계는 모든 사용자에게 같고 보여주는 방식만 사람과 상황에 따라 바뀐다.** 중심은 ② 기록이다. 이 앱이 "증인"인 이유다.

&#91;embedded content: 핵심 흐름 · 입력 3개, 판단 1개, 기능 3단계\]

- **① 안전**: 부상자가 있으면 119가 최우선, 고속도로면 촬영보다 대피가 먼저, 시내 경미 사고면 촬영 체크리스트(접촉 부위, 차선 위치, 상대 번호판) 후 이동.
- **② 기록**: 사고 시점 블랙박스 클립을 자동 저장하고, 조작 로그와 영상을 묶어 "이렇게 가다가 이렇게 사고가 났다"는 경위 설명문을 만든다. 기억이 흐려지기 전에 운전자 진술도 말로 남긴다.
- **③ 참고**: 차 데이터로 인정기준 도표 번호 후보를 좁혀 주고 포털로 연결한다. 몇 대 몇인지 단정하지 않는다.

### 강조점: 사고 클립 + 경위 설명문

**사용자가 상황을 파악하도록 돕는 핵심은 "영상 + 조작 로그"를 한 화면에서 시간순으로 맞춰 보여주는 것이다.**

1. **사고 클립 자동 저장**: 충돌 전후 구간 영상을 자동으로 잘라 저장하고 잠근다(해시). 보험사·상대방에게 보내기 쉽게 링크나 QR로 만든다. 공유 전에 상대 번호판·얼굴 가림을 고를 수 있다.
2. **조작 로그 동기화**: 조향각·브레이크·방향지시등·속도를 영상과 같은 시각축에 올린다.
3. **경위 설명문**: 두 데이터를 합쳐 시간순 문장으로 정리한다.

> 예시(가상의 값): 14:32:05 시속 31km로 주행 중 왼쪽 방향지시등을 켰다. 14:32:06 앞바퀴를 왼쪽으로 3° 꺾기 시작했다. 14:32:07 브레이크를 밟았고 0.8초 뒤 충돌했다. \[영상 분석 추정\] 같은 시각 왼쪽 차로에 차량 1대가 보인다.

**"비교적 객관적"이려면 지켜야 할 규칙**

- 문장은 기록된 값으로만 만들고, 문장마다 근거 시각과 값을 붙인다.
- 영상에서 읽은 내용은 "영상 분석 추정"으로 따로 표시하고, 사용자가 클립에서 직접 확인할 수 있게 한다.
- "급하게", "부주의하게"처럼 판단이 섞인 말은 쓰지 않는다.
- LLM은 문장만 다듬는다. 생성 후 숫자를 원본 로그와 다시 대조해 다르면 버린다.

**카메라 접근 경로**: 더 뉴 그랜저에는 인사이드 미러 내장 카메라로 운전자 시선을 보는 1열 모니터링 시스템(ICMU)이 있다([현대차그룹](https://www.hyundaimotorgroup.com/ko/news/hyundai-motor-company-the-new-grandeur)). 하지만 앱이 차량 카메라나 블랙박스 영상에 접근하는 SDK는 아직 공개 문서에 없다. 그래서 두 경로로 설계한다.

- 카메라 API가 열리면(운영국 확인 중): 사고 시점 클립을 자동으로 가져온다.
- 열리지 않으면: 사용자가 기존 블랙박스 영상을 불러오고, 앱이 GPS 시각으로 조작 로그와 맞춘다. PT 시연은 에뮬레이터에 실제 카메라가 없으므로 샘플 영상으로 한다.

## 사용 SDK·API

**공모전 개발 단계에서는 아래 SDK를 승인 없이 퍼미션 선언만으로 에뮬레이터에서 쓸 수 있다**(설명회 43:41, 49:24). 실제 앱마켓 배포 때만 퍼미션 승인이 필요하다.

| 쓰는 곳 | SDK·API | 가져오는 것 |
| --- | --- | --- |
| 기록 | Vehicle SDK · SteeringWheel | 앞바퀴 조향각, 도 단위, 왼쪽이 음수 (조회·변화 감지) |
| 기록 | Vehicle SDK · Brake | 브레이크 밟음 여부 (true/false) |
| 기록 | Vehicle SDK · TurnSignal | 방향지시등 상태 |
| 기록·안전 | AAOS 표준 Car API | 속도, 기어(P 여부) |
| 안전·기록 | FusedLocation SDK | 차량 위치 |
| 안전 | NaviHelper SDK | 현재 위치·경로 정보 (고속도로 여부 판단) |
| 기록 | SpeechToText SDK | 운전자 음성 진술 |
| 안전 | TextToSpeech SDK | 음성 안내, "차가 말해주는" 기록 요약 |
| 참고·교환 | 외부 LLM API, 자체 서버 | 문장 요약, 두 차 기록 교환 (외부 API·네트워크 허용, 설명회 49:05) |

**데이터 흐름**: 주행 중 최근 30초 정도를 메모리에 계속 덮어쓰며 보관 → 기어가 P로 바뀌거나 사용자가 "사고" 버튼을 누르면 그 구간을 저장하고 잠금(해시) → 요약 생성. 기록은 기본적으로 차 안에만 두고, 공유는 사용자가 고를 때만 한다.

영상은 카메라 API가 열리면 자동으로, 열리지 않으면 사용자가 불러온 블랙박스 파일로 받는다(위 "카메라 접근 경로"). 영상 장면 분석과 경위 설명문 문장 다듬기는 외부 비전·LLM API로 한다. 가속 페달은 Vehicle SDK 도메인 목록에 없어서 쓰지 않는다.

### 차의 움직임 추적: 되는 것과 안 되는 것

**내 차가 어떻게 움직였는지는 속도와 조향각으로 "추정 궤적"을 그릴 수 있다. 하지만 주변 차와의 거리, 주차 센서, 충돌 경고 같은 ADAS 센서 값은 일반 앱이 읽을 수 없다.** GPS는 시내·고속도로 구분에만 쓴다.

| 데이터 | 가능 여부 | 근거 |
| --- | --- | --- |
| 속도 | 가능 | AAOS `CAR_SPEED` 권한이 서드파티용(dangerous) ([AOSP Car 매니페스트](https://android.googlesource.com/platform/packages/services/Car/+/master/service/AndroidManifest.xml)) |
| 조향각 | 가능 | Pleos SteeringWheel. 핸들 회전각이 아니라 앞바퀴 조향각(도, 왼쪽이 음수)을 준다 ([Pleos](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/steering-wheel/entry)) |
| 크루즈 컨트롤 | 상태·설정 속도만 가능 | Pleos DrivingMode에 상태·목표 속도 함수만 있고 앞차 거리는 없음 ([Pleos](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/driving-mode/entry)) |
| 에어백 전개 | 가능 | Pleos Safety에 에어백 전개 여부 조회·변화 감지가 있음 → **큰 사고 자동 감지 트리거**로 쓴다 ([Pleos](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle/ai.pleos.playground.vehicle.api/safety/entry)) |
| 앞차 거리, 긴급제동·사각지대 경고 | 불가 | AAOS `READ_ADAS_STATES`가 시스템 전용(signature\|privileged), Pleos Safety에도 없음 |
| 주차 초음파 센서 | 불가 | AAOS `READ_ULTRASONICS_SENSOR_DATA`가 시스템 전용(signature\|privileged) |
| 자이로·가속도 센서 | 미확인 | Pleos 하드웨어 정책이 자이로 등 일부 센서는 제한될 수 있다고 명시 ([Pleos](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/platform-api-architecture)) |

**공식 문서로 확인한 세부 사항** (공모전 개발 환경 페이지에 연결된 Pleos 문서 기준)

- **조향각**: 앞바퀴 조향각을 도 단위로 주고, 왼쪽이 음수다. 핸들 회전각이 아니다. 갱신 주기를 지정하는 파라미터는 없고 값이 바뀔 때 리스너로 받는다. 퍼미션 `CAR_DRIVE`(normal).
- **브레이크**: 밟았는지 여부만 true/false로 준다. 얼마나 세게 밟았는지는 알 수 없다. 퍼미션 `CAR_DRIVE`(normal).
- **에어백 전개**: 좌석별로 전개 여부 변화를 받을 수 있다. 퍼미션 `CAR_SAFETY`(normal).
- **Virtual Console**에서 바꿀 수 있는 것: 기어, 브레이크 페달(0\~100%), 조향각(-540\~540°), 주행거리, 크루즈 상태·목표 속도, 방향지시등 등. **현재 속도, GPS 위치, 에어백, 카메라 항목은 없다.**

**추정 궤적 만드는 법**: 매 순간의 속도와 조향각을 이어 붙이면 차가 직진했는지, 좌회전했는지, 차선을 바꿨는지 모양을 그릴 수 있다(자전거 모델 기반 추측항법). Pleos가 주는 조향각이 이미 앞바퀴 각도라서 조향비를 가정할 필요가 없다. 차의 축거만 차종 기본값으로 가정한다.

- 경위 설명문 옆에 "충돌 10초 전부터의 추정 궤적" 미니맵을 그린다. 축척은 대략이며 "추정"으로 표시한다.
- 상대 차의 움직임은 이 데이터로 알 수 없다. 상대 차 위치는 영상 분석 추정이나 두 차 기록 교환(확장 2단계)으로만 채운다.
- 공모전용으로 공개될 SDK(설명회 37:08)에 ADAS 센서나 자이로가 들어 있으면 이 표가 바뀔 수 있다.

## 프로토타입 범위와 PT 시연

**12월 3일 PT까지 "한 대의 차에서 안전 → 기록 → 참고가 끝까지 도는 것"을 반드시 만들고, 두 차 교환은 여유가 있을 때 붙인다.** PT에서는 구조와 로직을 직접 설명해야 하므로(설명회 31:40) 구조를 단순하게 유지한다.

**반드시 만들 것 (1차 접수 시연 영상까지 목표)**

- [ ] 프로필 선택 화면: 상세·간결·음성 세 가지 안내 방식
- [ ] 기어 P 감지·에어백 전개 감지 → 안내 시작
- [ ] 위치로 고속도로·시내 구분 → 안전 안내 순서 분기
- [ ] 최근 30초 조작 로그 보관 (앞바퀴 조향각, 브레이크 밟음 여부, 방향지시등, 속도, 크루즈 상태)
- [ ] 테스트 모드: Virtual Console에 없는 속도·위치·에어백 값을 미리 만든 시나리오 파일로 재생
- [ ] 속도 + 조향각으로 충돌 10초 전부터의 추정 궤적 미니맵
- [ ] 사고 클립 저장: 샘플 블랙박스 영상에서 충돌 전후 구간을 잘라 로그와 같은 시각축에 표시
- [ ] 경위 설명문 생성: 로그 + 추정 궤적 + 영상 분석 → 시간순 문장, 문장마다 근거 값 표시
- [ ] STT로 운전자 진술 1건 저장, TTS로 설명문 읽어주기
- [ ] 사실 기록서 화면 (클립 링크 + 설명문, QR 또는 PDF)

**여유가 있으면**

- [ ] 에뮬레이터 두 대 + 서버로 두 차 기록 교환, 공동 사실 확인서
- [ ] 사고 유형 후보(인정기준 도표 번호) 제시

**PT 시연 시나리오**

1. 시내 교차로 접촉 사고, 숙련 운전자(간결 모드): Virtual Console로 좌회전 중 방향지시등·조향·브레이크를 조작 → 기어 P → 촬영 체크리스트 → 사고 클립과 조작 로그를 나란히 재생 → 경위 설명문 → 기록서.
2. 고속도로 사고, 고령 운전자(음성 모드): 같은 데이터인데 화면 대신 음성으로 "먼저 가드레일 밖으로"부터 안내.
3. (여유 시) 에뮬레이터 두 대를 나란히 띄워 A차·B차 기록을 교환하고 공동 사실 확인서 생성.

같은 사고 데이터가 **사람과 상황에 따라 다른 경험**으로 바뀌는 장면이 차량특화성과 맞춤화를 한 번에 보여준다.

## 사업성과 확장

**사고는 자주 나지 않으므로 MAU보다 "사고 1건당 가치"로 설득한다.** 심사 항목이 예상 MAU와 Retention을 묻기 때문에 이 약점을 먼저 인정하고 구조로 답한다.

- **시장 규모**: 과실 분쟁 심의 청구만 연 156,812건(2024). Pleos는 2030년까지 약 2,000만 대 탑재 계획 ([SBS Biz](https://biz.sbs.co.kr/amp/article/20000307412)), 기아는 2027년부터 적용 예정이라는 보도가 있음 ([ProPakistani](https://propakistani.pk/2026/08/01/hyundai-and-kia-cars-getting-major-smartphone-like-upgrade/)).
- **수익 구조 후보**: 개인은 무료. 보험사 사고 접수 연동, 렌터카·카셰어 업체의 기본 탑재(B2B)로 수익을 낸다. 보험사·렌터카사가 실제로 원하는지는 확인하지 않았으므로 기획서에는 가설로 쓴다.
- **Retention 보완**: 평소에는 쓸 일이 없다는 점을 숨기지 않는다. 대신 한 번 설치되면 사고 순간에 반드시 쓰이는 "보험 같은 앱"으로 포지셔닝한다.
- **사용 빈도를 늘리는 확장(가설, 2026-10-30 추가)**: 렌터카·카셰어 **대여·반납 때 차 외관 사진 기록**. 이미 만든 사고 촬영 가이드(위치별 촬영 순서)·SHA-256 잠금·PDF 기록서를 그대로 쓰므로 추가 개발이 작다. 렌터카 흠집 분쟁은 사고보다 자주 생기고, 대여할 때마다 쓰므로 렌터카 이용자에게는 "매 대여 1회"의 사용 빈도가 생긴다. 렌터카·카셰어 업체 기본 탑재(B2B) 가설과 바로 연결된다. 렌터카 흠집 분쟁 건수·업체 수요는 아직 근거를 찾지 않았다(미확인).
- **예상 MAU 계산 방식(숫자는 가정)**: Pleos 탑재 대수 × 앱 설치율 × (연간 사고 경험률 ÷ 12 + 렌터카 이용 비율 × 월 대여 횟수). 기획서에는 가정값과 출처를 표로 따로 적고, 가정임을 밝힌다.

**확장 단계**

1. 한 대 기록 + 경위 설명문 (공모전 범위, 지금 실차 앱은 영상 없음).
   - **확장 가능성 (2026-11-05 사용자 결정):** 앱이 차 내장 카메라(빌트인 캠 앞·뒤, 서라운드 뷰 앞 그릴·좌우 미러 아래·뒤 번호판 위)에 접근할 수 있으면, 여러 각도 영상을 조작 기록과 시간을 맞춰 정리해 보험사에 더 좋은 자료를 낼 수 있다. 시연에서는 이 모습을 게임으로 재현해 보여 준다. 지금 공개 SDK에는 영상 받는 API가 없고, 빌트인 캠 2 저장 영상은 앞·뒤뿐이라(공식 자료 기준) 서라운드 저장은 새 기능이다.
   - **가족 현대 계정 연결 (2026-11-09 사용자 결정, 계획):** 운전자가 미리 정한 가족에게 사고 사실 기록을 넘겨 가족이 연락과 자료 전달을 돕는다("따님에게 맡길까요?"). 보험금 청구·합의는 보험사가 요구하는 위임 절차가 필요하다. 현대 계정으로 보내는 것은 공개 경로가 확인되지 않은 확장 가능성이며, 시연은 앱 안 가족 연결로 하고 실제 연동은 운영국 협의 뒤에 진행한다. 위치·부상 정보는 사전에 항목별 동의를 받는다.
2. 두 차 모두 Pleos일 때 기록 교환, 공동 사실 확인서. 지금은 두 차가 모두 Pleos일 확률이 낮지만 탑재 차량이 늘수록 가치가 커진다.
3. 판결·분심위 결정례 학습 기반 과실비율 예측. 데이터 이용 허락과 법적 검토(손해사정 업무 해당 여부)를 확보한 뒤 착수한다.
4. 보험사 사고 접수·분심위 제출 양식 연동

## 운영국 문의와 남은 리스크

**프로토타입에 들어가기 전에 운영국(appdevchallenge@hyundai-partners.com)에 네 가지를 묻는다.**

- [ ] "현재 공개되지 않은 SDK"에 카메라 영상(외부 블랙박스·빌트인캠, 실내 ICMU) 접근이나 차량 제어가 포함되는지
- [ ] 공모전용 SDK에 자이로·가속도 센서나 ADAS 센서(앞차 거리, 주차 센서) 값이 포함되는지
- [ ] 앱이 주행 중 백그라운드에서 최근 수십 초를 계속 기록해도 되는지
- [ ] 휴학생은 대학생 부문인지 일반 부문인지
- [ ] 이메일 제목 형식 (설명회 안내와 홈페이지 표기가 다름)

**남은 리스크**

- **카메라 공개 여부가 핵심 기능을 좌우한다.** 열리지 않으면 사용자가 블랙박스 파일을 직접 불러와야 해서 "자동 저장"의 가치가 줄어든다.
- **Virtual Console로는 현재 속도, GPS 위치, 에어백을 재현할 수 없다.** 시연에서는 앱의 테스트 모드로 기록된 속도·위치·에어백 값을 재생해야 한다. 안드로이드 에뮬레이터 자체의 위치 설정을 Pleos 에뮬레이터에서 쓸 수 있는지는 아직 확인하지 않았다.
- 영상에는 상대 차 번호판, 보행자 얼굴 같은 타인의 개인정보가 담긴다. 공유 전 가림 기능과 동의 절차가 필요하다.
- LLM이 로그에 없는 값을 지어낼 수 있다. 생성 후 원본 값 대조를 빼면 "객관적 설명"이 무너진다.
- 블랙박스 영상 시각과 차량 로그 시각이 어긋날 수 있다. GPS 시각 기준 동기화 정확도를 시연 전에 확인한다.
- 추정 궤적은 축거를 가정하고 속도·조향각을 이어 붙이므로 오차가 쌓인다. 차선 단위 정확도를 주장하지 않고 "움직임의 모양"만 보여준다.
- 조향각은 값이 바뀔 때만 리스너로 들어오고 주기 지정 파라미터가 없다. 실차에서 얼마나 촘촘히 들어오는지는 확인할 수 없다.
- 브레이크는 밟음 여부만 알 수 있다. 경위 설명문에 "세게 밟았다" 같은 표현을 쓰면 안 된다.
- 위치 기록은 위치정보법상 동의 절차가 필요할 수 있다.
- 과실비율정보포털과 인정기준의 이용 조건은 원문 약관을 아직 보지 않았다.
- 사용자 유형 중 아이·가족 동승 운전자는 근거 수치가 없다. 기획서 전에 짧은 인터뷰 몇 건으로 보완한다.
