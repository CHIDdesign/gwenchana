# Hey, Why not ask the Car? — 아이디어 정리 (최신)

Oct 30, 2026 · 초기 노트(Oct 29) "최종 아이디어 정리"를 지금 구현 기준으로 다시 정리

> 표기: ✅ 구현·에뮬레이터 확인 · 🟡 구현했지만 일부 미확인 · ⬜ 아직 · (미확인) = 실제 차·문서로 확인 못 함

## 한 줄 정의

**사고 순간, 차가 "제3의 조수석 탑승자"가 되어 ① 운전자에게 맞춘 안전 행동을 순서대로 안내하고, ② 차가 직접 기록한 조작·충격 데이터로 판단 없는 시간순 사실 기록을 남기고, ③ 참고할 사고 유형과 공식 포털을 알려 주는 Pleos Connect 앱.**

- 판사가 아니라 **증인**이다. 누가 잘못했는지 판정하지 않는다.
- **실제 차가 주는 데이터만으로 동작한다.** Pleos SDK와 안드로이드 표준 API로 얻는 값만 쓰고, 시연용 게임(BeamNG.drive)은 그 데이터를 대신 만들어 주는 "대체본"이다. 게임만 아는 값은 정답 비교용으로만 표시한다.
- 같은 사고라도 **누가 운전 중이었는지, 어디서 무엇과 부딪혔는지**에 따라 안내가 달라진다.
- 빌트인캠·사고 자동 통보와의 차이: 영상을 남기는 게 아니라 **"몇 시 몇 초에 무엇을 했는지"를 문장으로 남기고, 사고 직후 할 일을 순서대로 이끈다.**

## 문제 정의 (초기 노트와 같음)

사고 직후 운전자는 당황해서 **안전 행동 순서를 놓치고, 기억이 엇갈리고, 무엇을 기준으로 다퉈야 할지 모른다.**

| 문제 | 근거 |
| --- | --- |
| 분쟁이 계속 늘어난다 | 과실비율 분쟁 심의 청구 2013년 26,093건 → 2024년 156,812건 ([보험연구원](https://www.kiri.or.kr/pdf/연구자료/연구보고서/nre2026-06_2.pdf)) |
| 서로 자기가 피해자라고 기억한다 | 분심위 심의 청구 운전자의 82.8%가 본인이 피해자라고 인식 ([파이낸셜뉴스](https://www.fnnews.com/news/202204201139201325)) |
| 사실 확인 주체가 약하다 | 대물 수리 대비 분쟁 비율 한국 5.4%(2024), 일본 0.03%(2023) ([보험연구원](https://www.kiri.or.kr/pdf/연구자료/연구보고서/nre2026-06_2.pdf)) |
| 판단 기준은 이미 일관적이다 | 분심위 결정 수용 90%, 소송 시 법원 인용 89%(2023) — 병목은 판단이 아니라 **사실 합의** |
| 현장 대처를 잘못하면 더 위험하다 | 고속도로 2차사고 치사율 54.3%, 일반사고의 6.5배, 고속도로 사망자 5명 중 1명 ([한국도로공사 2024-03-19](https://www.ex.co.kr/portal/biz/bbs/layout1/selectBoardArticle.do?bbsId=BBSMSTR_000000000183&nttId=26696)) |

한·일 차이의 원인을 경찰 개입 하나로 단정하지 않는다. "중립적 사실 확인이 분쟁을 줄일 수 있다"는 해석으로 쓴다.

## 사고 순간의 흐름 (지금 구현)

1. **감지** ✅ — 에어백 전개 / 가속도 2.5g / 속도 급감 + 충격. 감지 즉시 충돌 전 30초 기록을 저장.
2. **주행 중이면 안내줄** ✅ — 위쪽 띠에 "안전한 곳에 차를 세우세요" + [사고 아니에요]. 아래 내비는 그대로.
3. **정차하면 팝업** 🟡 — "괜찮으신가요?" [괜찮아요] [다쳤어요 → 바로 119 단계] [사고 아니에요]. 대답이 없으면 10초(에어백 3초) 뒤 자동 진행. (대답 버튼은 오늘 추가, 화면 확인 전)
4. **3D 상황 + 무엇과 부딪혔나** ✅ — 차가 먼저 추정하고 근거를 한 줄로 보여 줌. 운전자는 틀렸을 때만 바꿈.
5. **맞춤 대처 안내** ✅ — 고속도로(비트박스: 비상등 → 트렁크 → 가드레일 밖 대피 → 신고) / 시내(비상등). 다친 사람(119) → 상황별 신고 → 보호자 → 보험사·렌터카사. 전화 단계는 자동으로 넘기지 않고, 전화 뒤 돌아오면 하던 단계로.
6. **사진 촬영 안내** ✅ — 3D에 찍을 위치 번호와 영상 동선, 장면마다 각도 제안 그림.
7. **사고 장면 3D 재현** ✅ — 충돌 10초 전부터 3초 후까지.
8. **사실 기록** ✅ — 경위서(시간순 사실), [영상 분석 추정], 운전자 진술(STT, 안 되면 녹음), 읽어 주기(TTS), PDF 기록서, SHA-256 해시.
9. **③ 참고** ✅ — 비슷한 사고 유형 후보 + 근거 사실 + 과실비율정보포털.

### 사고 대상 자동 추정 (실차 데이터만)

| 근거 | 추정 |
| --- | --- |
| 카메라에 사람·자전거가 15m 안에 보임 | 사람·자전거 |
| 카메라에 차가 15m 안에 보임 | 차 |
| 멈춰 있을 때(3km/h 미만 또는 P) 충격 | 차 (다가와서 부딪힘) |
| 후진 중 뒤쪽 충격 | 벽·시설물 |
| 앞으로 가다 뒤쪽 충격 | 차 (뒤따르던 차) |
| 그 밖(예: 달리다 정면) | 모름 → 운전자 선택. 카메라 인식이 핵심 |

FCA 경고등은 보통 장치 꺼짐·고장 표시라 근거로 쓰지 않는다. 기준값은 추정이며 게임 사고로 조정한다.

### 경위서 규칙 (초기 노트와 같고, 코드로 강제)

- 문장은 기록된 값으로만, 문장마다 시각. 영상에서 읽은 것은 "[영상 분석 추정]"으로 분리.
- 판단 단어(과실·잘못·급하게 등) 금지 — 금지어 목록으로 검사.
- LLM은 문장만 다듬고, 숫자·부호·시각을 원본과 통째로 대조해 다르면 버리고 사실 목록을 쓴다(Validator).
- 브레이크는 밟음 여부만 → "세게" 금지. 가속 페달 값은 SDK에 없어 "속도가 1초에 4km/h 넘게 오름 = 가속 시작"으로만 적는다.

> 예시(실제 형식): 11:27:43.4 가속 시작 (속도 40.0 km/h) · 11:27:53.4 충격 감지 (최대 3.3g, 뒤 방향 [추정]) · 11:27:55.5 브레이크 페달 밟음 (속도 0.0 km/h) · 11:27:56.5 기어 P단으로 변경

| 기록 | Pleos Vehicle · Brake / TurnSignal / DrivingMode | 브레이크 밟음, 지시등, 크루즈 상태 |
| 감지·기록 | Pleos Vehicle · Safety | 에어백 전개, **계기판 경고등(Telltales 95종)** → 실차 비상등 = 좌·우 지시등 표시 동시 켜짐 |

| 기록·안전 | AAOS Car API | 속도, 기어 |
| 감지·궤적 | 안드로이드 가속도·**자이로** 센서 | 충격 크기·방향, 회전 속도 (실차 허용 미확인) |
| 기록 | 안드로이드 Camera2 | 사고 순간 사진 1장 (차에 앱용 카메라가 있을 때, 미확인) |
| 기록 | MediaPipe + EfficientDet-Lite0 (기기 안) | 사진·영상 속 차·트럭·버스·사람·자전거 위치 추정 |
| 안전·기록 | FusedLocation | 위치 |
| 안전 | NaviHelper | 도로 제한속도 (경로 안내 없이 오는지 미확인) |
| 기록 | SpeechToText / TextToSpeech | 운전자 진술 / 음성 안내·읽어 주기 |
| 기록 | 외부 LLM(중계 서버 → Claude) | 경위서 문장 다듬기, 프레임 설명 (동의한 경우만, 미배포) |

**SDK에 없는 것(확인함)**: 주변 차·물체(ADAS SDK 배포본 없음), 충돌 대상, 요레이트·가속도 차량 속성, 카메라 영상 API(화면 표시 상수만), 가속 페달, 비상등 조작, 차체 부위별 손상.

## 시연 구조 (게임 = 대체 데이터)

```
BeamNG.drive ─ 모드(askthecar.lua) ─UDP─▶ PC 브리지 ─┬─ Virtual Console ─▶ 에뮬레이터 차량 값 ─▶ Pleos 화면 + 앱(실제 SDK로 받음)
                                                       ├─ 에뮬레이터 센서(가속도·자이로) ─▶ 앱
                                                       ├─ 보조 통로: 에어백·도로 제한속도·비상등 (VC에 없는 값)
                                                       ├─ 시뮬레이터 정답(주변 차 위치·종류·벽 거리·손상 부위) ─▶ 비교용 표시만
                                                       └─ OBS 리플레이 = 시연용 블랙박스 영상
```

- 시동을 켜면 에뮬레이터 화면이 켜지고 운전자 선택 → 게임 지도 기반 우리 내비(게임 연동 때만, 실차는 Pleos 내비).
- 게임과 에뮬레이터의 문·후드·트렁크가 양방향으로 맞춰진다.
- 사고 3D는 **실차 방식 추정이 기본**이고, 게임 속 실제 위치는 파란 선·와이어로 겹쳐 "추정과 정답의 차이"를 보여 준다.
- 차·사람 3D 모델은 Kenney CC0 무료 모델. 에뮬레이터 주행 화면의 3D 모델은 현대차 자산이라 쓰지 않는다.

## 개인정보·보안 (Pleos 앱 심사 규정 반영)

- 🟡 **동의 화면**(오늘 작업 중): 주행 기록(필수), 위치, 음성 진술, 카메라 사진, 외부 AI 전송을 항목별로 알리고 "동의" 버튼으로만 동의. 철회하면 기록 삭제.
- 🟡 보관 기간: 사고 기록 30일, "사고 아니에요"·연습 기록 7일 뒤 자동 삭제. 주행 기록은 60초만 메모리.
- 기록은 차 안에만 두고, 공유는 운전자가 고를 때만.
- ⬜ 공유 전 번호판·얼굴 가림.

## 지금 상태 체크리스트

**초기 "반드시 만들 것"**
- ✅ 안내 방식 3가지(상세·간결·음성) — 간결 모드를 오늘 4단계로 줄임(확인 전)
- ✅ 에어백·충격·속도 급감 감지 → 안내 시작 (정차 판단 포함)
- 🟡 고속도로·시내 분기 — 제한속도·평균 속도 기반
- ✅ 조작 로그 60초 보관(조향·브레이크·지시등·속도·기어·크루즈·경고등·자이로)
- ✅ 테스트 모드 → BeamNG 실시간 연동 + 게임 없는 센서 주입 시험
- ✅ 추정 궤적 → 3D 장면·재현
- 🟡 사고 클립 + 조작 기록 동기 재생 — 게임 연동(OBS)에서만, 실차는 사진 1장
- 🟡 경위서 — 사실 목록은 됨, LLM 다듬기는 중계 서버 미배포
- 🟡 STT 진술·TTS 읽기 — TTS 서버 인증 401(기기 음성으로 대체)
- 🟡 사실 기록서 PDF — 차에 공유받을 앱이 없음, QR 없음

**추가로 생긴 것**: 운전자 선택, 주행 중 안내줄, 사고 대상 추정, 비상등 확인, 트렁크 버튼, 사진 3D·각도 가이드, ③ 참고 화면, 게임 지도 내비, 전화 후 복귀, 라이트·다크 모드, 문·트렁크 게임 연동

**다음 (심사 2차 평가 기준)**
- P0: 동의 화면·삭제, 감지 보완, 오탐·연습 기록 분리, 팝업 대답 버튼, 간결 모드 — 오늘 진행 중
- P1: **대피 뒤 안내·기록을 휴대폰으로(QR)**, **보험사 원터치 전달 묶음**(기록서·로그·해시·진술·위치 + 접수 양식 미리 채우기), 차 안 "사고 났어요" 버튼, 게임 없이 도는 시연 경로, TTS 401
- P2: 실차 블랙박스 파일 불러오기, 렌터카 대여·반납 사진 기록, 고령자 버튼 크기, 번호판 가림
- 여유 시: 두 차 기록 교환, 아이·가족 동승 유형

## 사업성과 확장

**사고는 자주 나지 않으므로 MAU보다 "사고 1건당 가치"로 설득한다.**

- **시장**: 과실 분쟁 심의 청구 연 156,812건(2024). Pleos 2030년까지 약 2,000만 대 탑재 계획 ([SBS Biz](https://biz.sbs.co.kr/amp/article/20000307412)).
- **수익 가설**: 개인 무료. 보험사 사고 접수 연동(원터치 전달 묶음), 렌터카·카셰어 기본 탑재(B2B). 수요는 확인 안 함 → 기획서엔 가설로.
- **평소에 쓸 이유(가설)**: 렌터카·카셰어 **대여·반납 때 외관 사진 기록** — 이미 있는 촬영 가이드·해시·PDF를 그대로 재사용. 렌터카 분쟁도 사고만큼 흔하다(수치 미확보).
- **가족 현대 계정 연결(2026-11-09 계획)**: "따님에게 맡길까요?"를 고르면 미리 정한 가족이 연락과 자료 전달을 돕는다. 청구·합의는 위임 절차 필요. 현대 계정 전송은 공개 경로 미확인인 확장 가능성, 시연은 앱 안 가족 연결로, 실제 연동은 운영국 협의 뒤. 위치·부상 정보는 항목별 사전 동의.
- **확장 단계**: ① 한 대 기록(공모전 범위) → ② 두 차 Pleos 기록 교환·공동 사실 확인서 → ③ 보험사 접수·분심위 양식 연동 → ④ 결정례 기반 참고 강화(데이터 허락·법률 검토 뒤).
- 수상해도 앱마켓 입점은 보장되지 않음(공모전 안내).

## 남은 리스크

- **실차 데이터 통로**: 가속도·자이로·카메라가 일반 앱에 안 열려 있으면 감지는 에어백·속도 급감으로, 사고 대상은 운전자 선택으로 떨어진다. 센서 축은 에뮬레이터 기준(실차 장착 방향 미확인).
- **시연 의존성**: 게임·OBS·에뮬레이터를 GPU 하나로 → 튕김 이력. 게임 없이 도는 대체 시연 경로 필요.
- **TTS 401**, 중계 서버 미배포, 행사장 인터넷.
- **차에서 내린 뒤** 안내·기록이 차 화면에 갇혀 있음 → QR·휴대폰 넘기기.
- 추정값(충격 방향 구간, 사고 대상 기준, 3D 상대 위치)은 근사 — 차선 단위 정확도를 주장하지 않는다.
- 영상·시각 동기: 영상은 PC 시계, 로그는 에뮬레이터 시계(같다고 가정).
- 아이·가족 동승 유형 근거 없음, 과실비율정보포털 이용 조건 원문 미확인.
