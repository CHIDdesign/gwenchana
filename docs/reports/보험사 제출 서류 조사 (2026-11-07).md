# 보험사 제출 서류 조사 (2026-11-07)

조사 방식: 웹 검색 + 일부 페이지 읽기. 보험사 공식 페이지는 대부분 로그인·동적 페이지·OZ Viewer 때문에 본문을 못 읽음. **확인 못 한 것은 "미확인"으로 적음.** 추측으로 채우지 않음.

## 앱에 바로 쓸 결론

1. **보험사 공통 표준 서식은 없다**(확인된 범위에서). 사고경위서도 보험사가 담당자를 통해 자기 양식을 주는 방식으로 보인다(공식 양식 다운로드 페이지는 못 찾음). 그래서 앱 PDF는 "보험사 양식을 대신하는 것"이 아니라 **"담당자에게 붙여 주는 첨부 자료(사실 기록서)"**로 만드는 게 안전하다.
2. 현실적인 보내는 방법 (우선순위)
   - ① **폰에서 PDF·사진을 공유 시트로 보험사 앱/카카오톡/문자/이메일에 첨부** (앱이 PDF를 만들어 폰 공유 기능으로 넘김). 삼성화재 앱은 갤러리에서 보험금 청구 서류를 첨부할 수 있다고 확인됨.
   - ② 사고 접수 후 배정된 **담당자에게 직접 전달**(전달 경로는 담당자가 알려 줌, 보험사별 미확인).
   - ③ 보험사 API로 자동 전송은 **불가능으로 봐야 함**(공개 API·표준 못 찾음).
3. **PDF 권장 구성**(과실·책임 판단 문구 금지):
   - 표지: 기록 번호, 생성 시각(KST), 앱 이름·버전, "이 문서는 판단이 아니라 기록입니다"
   - 운전자·차량: 이름, 연락처, 차량번호, 차종, 보험사, 증권번호(사용자 입력)
   - 사고 개요: 일시, 장소(GPS 위도·경도, 주소는 미확인 시 생략), 날씨/도로는 입력 시에만
   - 시간순 차량 기록: 타임스탬프 + 속도, 브레이크, 조향, 지시등, 에어백, 충격 크기·방향
   - 사진(번호·촬영 시각), 영상이 있으면 파일명·길이·SHA-256
   - 운전자 진술(본인 말 그대로, "[진술]" 표기), 상대 차량·목격자·경찰 신고 여부(입력칸)
   - 상대방 정보 칸(성명, 연락처, 차량번호, 보험사) — Constat 및 ACORD 2와 비슷
   - 부상 여부(해당 없음/있음), 현장 도움 요청 이력
   - 무결성: 각 파일 SHA-256, PDF 생성 시각, 해시 계산 방법 설명, 한계 문구(아래 5절)
   - 정직 문구: "영상 분석 추정"·"시뮬레이터"처럼 출처 구분 표기
4. 법적 효력은 보장하지 말 것. "원본 변조가 없음을 해시로 확인할 수 있다" 정도까지만 쓰고, "법원에서 인정된다"는 쓰지 않는다.

## 1. 보험사가 요구하는 서류와 양식

확인된 것
- 일반 청구 구성은 보험금 청구서 + 신분증 사본 + 사고 입증 서류(예: 교통사고사실확인원)로 안내됨. 출처: [Chubb 청구서류·양식 안내](https://www.chubb.com/kr-kr/claims-service/claims-documents-forms.html) (일반 보험 안내, 자동차 전용 아님), 검색 요약 기준.
- KB손해보험 페이지에 청구서, 샘플, 위임장, 지급결의서 등 서식이 PDF 또는 OZ Viewer로 제공됨. 자동차 전용 구비서류 표는 읽지 못함. 출처: [KB손보 서식 페이지](https://www.kbinsure.co.kr/ceo/CG205020002.ec)
- KB 안내(검색 요약): 자동차보험 사고사실확인원 또는 지급결의서, 수리비 지급상세내역서(자사 처리 시 생략 가능), 부상등급 명기된 처리내역서가 필요할 수 있음. 보험사별로 다름. (원문 직접 확인은 못 함)
- 삼성화재 "자동차보험금 청구서" 샘플 PDF가 공식 사이트에 있음: [claim_car_attack_sample.pdf](https://samsungfire.com/download/claim/claim_car_attack_sample.pdf). 검색 요약상 최종 운전자 정보(성명·주민번호·연락처·피보험자와의 관계), 피보험 차량 정보, 피보험자 연락처 칸이 있음. 파일이 압축 스트림이라 **전체 필드는 못 읽음(미확인)**.
- 일반 서식 사이트의 사고경위서는 일시, 장소, 운전자, 차량, 처리 경과, 사고 내용을 적는 구성: [bizforms 자동차보험금 지급청구서](https://www.bizforms.co.kr/form_view/form_44914.asp) 등. **보험사 공식 양식이 아님.** 청구서에는 "사고경위가 틀림없음을 확인, 사실과 다르면 수령 보험금 반환" 문구가 들어감(위 사이트 검색 요약).
- 삼성화재는 2024년 9월부터 모바일 본인인증 + 공공 마이데이터 동의로 주민등록 서류 없이 자동차보험금 청구 가능: [SBS Biz](https://biz.sbs.co.kr/amp/article/20000192457), [korea.kr](https://www.korea.kr/news/policyNewsView.do?newsId=148934063) (검색 결과 요약, 본문 직접 확인은 안 함).

미확인
- 현대해상, DB손보, 메리츠, 한화, 롯데, 흥국, AXA, 캐롯의 자동차 대물·자차·대인별 공식 구비서류 목록과 사고경위서 공식 양식 다운로드 URL: **못 찾음**.
- 블랙박스 영상이 "필수 서류"인지: 못 찾음. 영상은 과실 협의 때 담당자가 요청하는 자료로 쓰인다는 일반 글만 있음([tilnote 가이드](https://tilnote.io/pages/6a3967f9478fbed2737d899b), 신뢰도 낮은 블로그).

## 2. 제출 경로

확인된 것
- 삼성화재 앱: 자동차 사고접수 기능, 카메라 촬영 및 갤러리에서 보험금 청구 서류 첨부(앱 권한 설명). 출처: [App Store 삼성화재](https://apps.apple.com/app/id409967827)
- AXA다이렉트(2013~2014 기사): 웹·앱 사고 접수, 파손 사진 기록, 목격자 음성 등록, 카카오톡 플러스친구로 사진 전송. 현재 운영 여부 **미확인**. 출처: 검색 결과 기사들(예: [tilnote](https://tilnote.io/pages/6a3967f9478fbed2737d899b) 인용)
- 문자로 사진 제출 요청을 받고 앱에서 올리는 방식은 흥국화재 마일리지 앱 사례만 확인(사고 접수용 아님, 서비스 종료 안내): [모바일박스 App Store](https://apps.apple.com/app/id684629494)
- KB손보: 고객센터 이메일 cscenter@kbinsure.co.kr, 전화, 앱 있음. 서류용 팩스·모바일 업로드는 본문에서 식별 못 함.

미확인
- 임의 PDF/영상 허용 여부, 파일 용량 제한: 어느 보험사도 못 찾음.
- 팩스 번호·담당자 이메일·카카오톡 채널 공식 안내: 못 찾음(담당자별로 다를 것으로 추정, 미확인).

## 3. 전자 청구용 공개 API·표준

- 자동차 사고 접수·서류를 외부 앱이 보험사로 보내는 **공개 API나 표준 서식은 못 찾음**(보험신용정보원, 손해보험협회, 보험개발원 모두 해당 자료 없음 → 없다고 단정은 못 하고 "찾지 못함").
- 관련 있는 제도: 실손의료보험 청구 전산화(실손24)는 보험업법 개정으로 병원·약국이 청구서류를 전자 전송하는 것으로, **실손 대상**. 자동차보험 적용 여부는 **미확인**. 출처: [대륜 뉴스레터](https://www.daeryunlaw.com/newsletter/news/77), [메디게이트](https://medigatenews.com/news/1238929545)
- 따라서 앱의 "직접 전송"은 보험사와 제휴(별도 협의)가 있어야 가능. 공모전 범위에서는 **공유 시트 방식**이 현실적.

## 4. 해외 표준 (확장용)

- **유럽 사고 신고서(Constat amiable)**: 양 당사자 공동 작성·서명, 사고 일시·장소, 부상·물적 피해, 증인, 차량·보험, 운전자, 상황 체크박스 1~17번, 사고 약도(13번), 표시 칸 수 기재, 서명. 서명은 책임 인정이 아니라 사실 합의라는 설명이 있음. 출처: [Enterprise 안내](https://enterprise.ch/en/go-helpcenter/european-accident-report), [벨기에 경찰](https://www.police.be/5328/node/672), [Connexion France](https://connexionfrance.com/practical/what-to-do-in-case-of-a-road-accident-in-france/703785). 법적 의무 아님(프랑스). 우리 앱은 "상황 체크박스(책임 암시)"는 가져오지 말 것.
- **ACORD 2 자동차 손실 통지서**: 섹션 = 보험계약자 연락처, 사고(Loss), 보험 증권 정보, 보험 가입 차량, 피해 재산·차량, 부상자, 목격자·동승자. 출처: [ACORD 2 샘플](https://www.jsausa.com/wp-content/uploads/2017/05/Auto-Loss-Notice-ACORD-2.pdf), [ABBYY 설명](https://www.abbyy.com/marketplace/assets/host/abbyy/document-skill/acord-2-automobile-loss-notice/). ACORD AL3(텍스트)/XML 스키마는 ACORD에서 제공(회원·구매 필요 추정, 미확인): [Informatica AL3](https://docs.informatica.com/cloud-common-services/administrator/current-version/data-services-repository/data-service-reference/acord-al3.html)
- 미국 보험사 FNOL API 목록: **미확인**(이번 조사에서 공개 문서 못 찾음).

## 5. 증거 무결성

확인된 것
- 디지털 영상은 원본 동일성·무결성 입증이 중요하고, 블랙박스 SD카드 교체 주장 등에서 진정성립이 쟁점. 형사소송법 313조 적용 논의 있음. 출처: [알법 칼럼](https://albup.co.kr/page/column_detail.php?content_id=3041), [koreascience 논문](https://koreascience.kr/article/JAKO201521052964489.pdf) (요약만 확인).
- 해시 일치 = 내용이 안 바뀜 확인. **작성 시점은 해시로 증명 못 함** → 타임스탬프 필요. 이 부분은 일반 원리를 설명하는 해외 자료이며 한국 법 근거는 아님. 출처: [click&sign](https://blog.clickandsign.eu/en/what-is-a-timestamp-and-why-is-it-important-for-electronic-signatures/)
- 전자거래기본법이 전자문서를 일반 문서와 동등히 보려 하나 실제 쟁점은 증거 채택이며 자유심증주의라는 논문 초록 있음. 출처: 검색 결과 [earticle](https://m.earticle.net/Article/A407989).

미확인
- "해시값 검증으로 증거능력이 인정된다"는 **한국 대법원 판례: 못 찾음**. 전자문서법·전자서명법 조문은 law.go.kr가 읽히지 않아 직접 확인 못 함.
- 자체 생성 PDF의 SHA-256이 법적으로 어떤 효력인지, 공인전자문서센터·국내 타임스탬프 기관(KISA 등) 이용 가능성: 미확인.
- 실무 권장(내 판단, 법적 근거 아님): PDF에 "앱이 계산한 값이며 제3자 인증이 아님"을 명시하고, 가능하면 폰 서버나 외부 타임스탬프로 시각 증명을 추가하는 것을 로드맵으로 둠.

## 6. 현대·Pleos 로고

- 현대자동차 CI 안내: 로고는 임의 수정 불가, 배경별 버전·최소 크기·여백 규정. 제3자 앱 사용 허가 절차는 페이지에 안 보임. 출처: [현대자동차 CI](https://www.hyundai.com/kr/ko/info/ci), [CI 색상](https://www.hyundai.com/kr/ko/info/ci/ci-color)
- 제네시스 사이트(계열사)는 사전 허락 필요, 후원·보증으로 오인될 용도 금지, 로고는 상표 등록 명시: [제네시스 저작권 안내](https://www.genesis.com/kr/ko/terms-of-use/copyright.html). 현대차 본사에 그대로 적용된다고는 단정 못 함.
- Pleos 공모전 유의사항에서 로고 조항: 못 찾음(document.pleos.ai와 공모전 페이지 본문은 이번에 못 읽음).
- 결론(판단): **"데이터가 진짜임"을 보증하는 문서에 현대·Pleos 로고를 넣지 말 것.** 오인 위험이 큼. 필요하면 "Pleos Connect SDK로 수집" 같은 텍스트 사실 표기만 하고 로고는 운영국 허락 후.

## 검증 한계
- 웹 검색은 보험사 공식 페이지를 거의 못 가져왔고(동적·인코딩 문제), 위 인용은 많은 부분 검색 요약에 의존. 제출 전 각 보험사 앱·고객센터에서 직접 확인 필요.
- 고객센터 전화번호는 기억에 의존한 것이라 이 보고서에 넣지 않음.
